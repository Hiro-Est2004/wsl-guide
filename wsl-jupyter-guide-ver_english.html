Setting Up a Python Development Environment
on Windows Subsystem for Linux (WSL)

(2026 Edition)
The WSL installation process has been greatly simplified. Previously, you had to run multiple dism.exe commands, manually download the kernel, and install Ubuntu from the Microsoft Store. Now it's done with a single command.
Integration with VS Code has also become much easier.
Table of Contents

    This guide covers how to install WSL to run a Linux-based OS (Ubuntu) on Windows, and how to set up a Python development environment on top of it. Follow the steps from top to bottom — skipping or reordering steps may cause issues.

    1. Installing WSL + Ubuntu

    In the past, WSL required multiple commands and manual downloads. Now, a single command installs WSL2 and Ubuntu together.

    Installation Steps

    1
    Open PowerShell as Administrator
    Right-click the Start menu and select "Windows PowerShell (Admin)" or "Terminal (Admin)".
    2
    Run the following command 
    wsl --install -d Ubuntu
    This single command automatically handles all of the following:
    • Enabling the WSL feature
    • Enabling the Virtual Machine Platform feature
    • Installing the WSL2 kernel
    • Installing the latest Ubuntu LTS
    Note: Running wsl --install without any options may not automatically install Ubuntu in some cases. Always include -d Ubuntu.
    About version selection: -d Ubuntu installs the latest LTS available at the time (currently 24.04). To pin a specific version, use -d Ubuntu-24.04.
    Run wsl --list --online to see all available distributions.
    3
    Restart your PC (required)
    4
    Launch Ubuntu
    After restarting, Ubuntu does not start automatically. Launch it manually using one of the following:
    • Type wsl in PowerShell or Command Prompt and press Enter
    • Search for "Ubuntu" in the Start menu and click it
    5
    Set up a username and password
    On first launch, you will be prompted to create a Linux username and password. Enter anything you like. 
    Enter new UNIX username: (enter any username)
New password: (enter any password — input is hidden)
Retype new password: (re-enter the same password)
passwd: password updated successfully
Installation successful!

    2. Python Environment Setup

    All steps from here onwards are run in the WSL (Ubuntu) terminal, unless otherwise specified. If WSL is not running, launch it by searching for "Ubuntu" in the Start menu, or by typing wsl in PowerShell.

    2.1 Configuring the PATH

    By default, the WSL PATH includes the Windows PATH. If Python is installed on the Windows side, this can cause conflicts. The following setting makes the WSL PATH independent of Windows.

    Open the configuration file using the command below:

    About nano: nano is a text editor that runs inside the terminal. Running the command opens the file directly in the terminal, where you can edit it right away. 
    $ sudo nano /etc/wsl.conf

    Add the following to the opened file:

    [interop]
appendWindowsPath = false

    When done editing, save and exit with the following steps:

    1. Press Ctrl + X to begin exiting
    2. Press Y to confirm saving
    3. Press Enter to confirm the filename

    After saving, run the following in PowerShell to restart the WSL distribution:

    wsl --shutdown

    2.2 Updating apt

    $ sudo apt update
$ sudo apt upgrade -y

    Install the basic packages required for building:

    $ sudo apt install -y build-essential
    About build-essential: build-essential is a meta-package that installs a collection of tools needed to compile source code, including gcc (C/C++ compiler), make, and libc development headers. It is also used internally by pyenv when building Python.

    2.3 Installing pyenv

    Install pyenv, a tool for managing multiple Python versions.

    First, install the required dependencies:

    $ sudo apt install -y git libedit-dev libncurses5-dev libbz2-dev \
    libreadline-dev libsqlite3-dev zlib1g-dev libssl-dev \
    libffi-dev liblzma-dev

    Clone pyenv:

    $ git clone https://github.com/pyenv/pyenv.git ~/.pyenv

    Add the following to the end of ~/.bashrc. You can use nano to edit it easily:

    1
    Open the file 
    $ nano ~/.bashrc
    2
    Use the ↓ arrow key to scroll to the bottom, then add the following 
    export PYENV_ROOT="$HOME/.pyenv"
export PATH="$PYENV_ROOT/bin:$PATH"
eval "$(pyenv init -)"
    3
    Save and exit
    Ctrl + X → Y → Enter
    4
    Apply the changes 
    $ source ~/.bashrc

    Verify the installation:

    $ pyenv --version
pyenv 2.x.x

    2.4 Installing Python

    List the last 5 available stable versions:

    $ pyenv install --list | grep -E "^\s+3\.[0-9]+\.[0-9]+$" | tail -5

    Check the latest 3.12 releases:

    $ pyenv install --list | grep -E "^\s+3\.12\.[0-9]+$" | tail -3
    $ pyenv install 3.12.13
    The following warning may appear during installation — it is safe to ignore: 
    WARNING: The Python tkinter extension was not compiled and GUI subsystem has been detected. Missing the Tk toolkit?
    tkinter is a GUI library for building desktop apps with buttons, input fields, and windows. It is not needed for data analysis or Jupyter, so this warning can be safely ignored.
    Which version to choose (as of May 2026):
    3.14 is the latest but may be unstable as it was just released. 3.12 is currently stable and recommended. 3.8 reached end-of-life in October 2024 and should not be used for new environments.

    Set the installed version as the default:

    $ pyenv global 3.12.13
$ python --version
Python 3.12.13

    Update pip:

    $ pip install --upgrade pip

    3. Installing Jupyter

    Install JupyterLab.

    JupyterLab vs Jupyter Notebook:
    JupyterLab is the recommended option as it offers more features. It is a superset of Jupyter Notebook, with a file browser, tab support, and more. 
    $ pip install jupyterlab

    How to Launch (browser-based)

    If you are using the Jupyter extension in VS Code, you can open .ipynb files directly without this step. The command-line launch method is useful when you want to use Jupyter in a browser. 
    $ jupyter lab

    After launching, a URL like the one below will appear in the terminal. Copy and paste it into your browser:

    http://localhost:8888/lab?token=xxxxxxxxxxxxxxxx

    To stop the server, press Ctrl + C twice in the terminal.

    4. Integrating with VS Code

    In older versions, this required alias configuration and manual PATH setup. Now it works simply by installing the WSL extension.

    Setup Steps

    1
    Install VS Code on the Windows side
    Download and install from https://code.visualstudio.com/.
    During installation, make sure "Add to PATH" is checked.
    2
    Install the WSL extension
    Open the Extensions tab in VS Code, search for WSL, and install it.
    Extension ID: ms-vscode-remote.remote-wsl
    3
    Add the VS Code PATH to WSL
    Run the following command (replace username with your actual Windows username): 
    $ echo 'export PATH="$PATH:/mnt/c/Users/username/AppData/Local/Programs/Microsoft VS Code/bin"' >> ~/.bashrc
$ source ~/.bashrc
    4
    Launch VS Code from the WSL terminal using code .
    Navigate to your working directory and run: 
    $ cd ~/myproject
$ code .
    On the first run, VS Code Server will be installed automatically. Subsequent launches will be instant.

    Recommended VS Code Extensions

    Search for and install the following in the Extensions tab.

    ExtensionIDPurpose
    WSLms-vscode-remote.remote-wslWSL integration (required)
    Pythonms-python.pythonCode completion and debugging
    Jupyterms-toolsai.jupyterEdit and run .ipynb files directly in VS Code

    5. Tips & Shortcuts

    Accessing Dropbox from WSL

    $ cd /mnt/c/Users/[WindowsUsername]/Dropbox

    WSL Management Commands

    # List installed distributions
wsl --list --verbose

# Shut down WSL
wsl --shutdown

# Backup (export)
wsl --export Ubuntu ubuntu-backup.tar

# Restore (import)
wsl --import Ubuntu C:\WSL\Ubuntu ubuntu-backup.tar
